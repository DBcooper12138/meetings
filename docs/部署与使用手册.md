# 会议发布与参会确认系统 · 部署与使用手册

> 一套自己就能维护的会议系统：在后台发布会议 → 生成一条专属链接 → 发到微信群 → 参会人在手机上填姓名、选"参加 / 不参加" → 结果自动汇总回后台，可看、可统计、可导出 Excel。

## 1. 它能做什么

| 功能 | 说明 |
| --- | --- |
| 发布会议 | 填写会议名称、日期时间、地点、主办部门、主持人、联系人、议程，可设填报截止时间 |
| 选择参会人员 | ① 按**类别**整类勾选（处长 / 院长 / 办公室主任 / 党总支书记）；② 搜索后**单独**挑人。两者可混用 |
| 生成参会链接 | 每场会议自动生成一条唯一链接 + 二维码，发到群里即可 |
| 二级网页填报 | 参会人打开链接 → 看到会议信息 → 填本人姓名 → 点"参加"或"不参加" → 不参加时填原因 → 可填备注 |
| 后台实时汇总 | 会议窗格显示"参会 / 不参会 / 待确认 / 回执率"；点进详情可看每个人的状态、原因、备注、回执时间；详情页每 30 秒自动刷新 |
| 随时可改 | 填过之后重新打开同一条链接再提交一次即可覆盖，不会出现重复记录 |
| 名单管理 | 后台可增、删、改人员；支持 Excel / CSV 导入；可导出当前名单 |
| 数据长期保存 | 所有会议与回执存在云端数据库，挂上 GitHub 之后**以后任何时候打开都还在**，可用于统计 |
| 导出统计 | 单场导出 / 全部会议导出（Excel，每场一个工作表）/ 总览统计表 / 人员名单 |

**没有的**：短信通知、微信服务号推送、签到打卡、附件上传。需要的话可以再加。

## 2. 两个"网页"是怎么分工的

只有一个网页文件，但用两种"视图"：

```
一级网页（后台，你自己用）
  https://你的用户名.github.io/仓库名/#/meetings
      ├─ 会议看板      #/meetings
      ├─ 发布会议      #/new
      ├─ 会议详情      #/meeting/<会议id>
      ├─ 名单管理      #/roster
      └─ 导出统计      #/export

二级网页（发给参会人，别人用）
  https://你的用户名.github.io/仓库名/#/s/<会议token>
      └─ 填姓名 → 选参加/不参加 → 提交
```

两者共用同一个云端数据库 —— 所以别人在任何地方用手机填完，你后台刷新就能看到。

> `#` 后面的内容叫"哈希"，浏览器不会把它发给服务器，所以 GitHub Pages 这种静态托管也能正常路由，不需要任何服务器配置。

## 3. 第一次配置（约 15 分钟）

只需配一次。总共三件事：**建数据库 → 建表 → 填两个参数**。

### 3.1 注册 Supabase（免费，国内可直连）

1. 打开 <https://supabase.com> → `Start your project` → 用邮箱注册并登录。
2. 点 `New project`：
   - **Name**：随便填，例如 `meeting`
   - **Database Password**：随便设一个强密码，**记下来**（本系统不用它，但以后可能用到）
   - **Region**：选 **Southeast Asia (Singapore)** —— 国内访问最快
   - 点 `Create new project`，等 1~2 分钟初始化完成。

### 3.2 建表（把一段 SQL 粘进去执行）

1. 左侧菜单点 `SQL Editor` → `New query`。
2. 用记事本打开项目里的 **`supabase/01_schema.sql`**，**全选、复制**。
3. 粘贴到 SQL 编辑框里，点右下角 `Run`（或按 `Ctrl+Enter`）。
4. 看到 `Success. No rows returned` 就成功了。这一步会建好 4 张表和 3 个专用函数。

### 3.3 设置后台口令

在同一个 SQL Editor 里，新开一个 query，执行下面这一行（把口令换成你自己的）：

```sql
select public.set_admin_secret('你的后台口令');
```

> - 口令至少 4 位，建议 8 位以上、带数字和字母。
> - 数据库里只存这个口令的哈希值，**不存明文**。
> - 想改口令，重新执行这一行即可。
> - **执行完请把这一行删掉**，别把明文口令留在 SQL 历史记录里。

### 3.4 把两个参数填进 config.js

1. 在 Supabase 左侧点 `Project Settings`（齿轮图标）：
   - `Data API` 页里找到 **Project URL**，形如 `https://abcdefghijk.supabase.co`
   - `API Keys` 页里找到 **anon public** 密钥（一长串以 `eyJ` 开头的字符）

   > ⚠️ 一定要用 **anon public**，**绝对不要**用 `service_role`。后者等于数据库总钥匙，放进网页等于公开。

2. 用记事本打开项目里的 **`config/config.js`**，替换前两行：

   ```js
   SUPABASE_URL: 'https://abcdefghijk.supabase.co',
   SUPABASE_ANON_KEY: 'eyJhbGciOi...很长一串...',
   ```

3. （可选）把第 3 行 `ADMIN_SECRET` 填成你刚才设的口令，这样每次打开后台不用手输：

   ```js
   ADMIN_SECRET: '你的后台口令',
   ```

   不填也行 —— 打开后台时会弹框让你输入一次，之后记在这台电脑的浏览器里。

4. 保存文件。

### 3.5 本地先试一下

直接双击 `index.html` 用浏览器打开：

- 如果配置正确 → 出现会议看板，顶部没有黄色横幅。
- 如果提示"请输入后台口令" → 输入口令，点"进入后台"。
- 如果顶部有黄色横幅"当前是本机模式演示" → 说明 `config/config.js` 还没填好。此时功能都能点，但数据只存在这台电脑的浏览器里，**别人用手机打不开你的会议链接**。横幅右上角「☁ 接入云端数据库」按钮里写着完整步骤。
- 如果提示"数据库里还没有建表" → 回到 3.2 重做一遍 SQL。

进去后先去 **名单管理 → 写入初始 55 人名单**，把基础名单灌进去。

> 说明：直接双击本地文件（`file://` 打开）时，Supabase 的请求也能工作；但**参会链接只有在发布到 GitHub Pages 之后别人才能打开**，因为本地文件路径没法发给别人。

## 4. 发布到 GitHub Pages（别人才能访问）

### 4.1 注册 GitHub

<https://github.com> → `Sign up` → 用邮箱注册。用户名会出现在网址里，建议用拼音或英文。

### 4.2 新建仓库

1. 右上角 `+` → `New repository`。
2. **Repository name**：例如 `meeting`（网址里会用到）
3. 选 **Public**（私有仓库的 Pages 需要付费；本项目不含任何密钥明文，公开安全 —— 见第 10 节）
4. **不要**勾选 `Add a README file`
5. 点 `Create repository`。

### 4.3 上传文件（网页点几下就行，不需要装 Git）

1. 在新仓库页面点 `uploading an existing file`。
2. 打开项目文件夹 `meeting-system`，**把下面这些拖进去**：

   | 要传 | 说明 |
   | --- | --- |
   | `index.html` | 入口页面 |
   | `css` 文件夹 | 样式 |
   | `js` 文件夹 | 程序 |
   | `config` 文件夹 | ★ 里面有你的 Supabase 参数，必须传 |
   | `supabase` 文件夹 | 建库脚本（留档用，运行时不需要） |
   | `docs` 文件夹 | 本手册 |
   | `README.md` | 仓库首页说明 |
   | ❌ `_dev` 文件夹 | **不要传**，那是开发自检用的测试工具 |

3. 拉到底部点 `Commit changes`。
4. 传完后仓库首页应该能看到 `index.html`、`css/`、`js/`、`config/`。

> 小提示：拖文件夹上去时 GitHub 会保留目录结构。如果只上传了文件夹里的文件而目录结构丢了，
> 页面会白屏 —— 此时看浏览器控制台（F12）会报找不到 `js/app.js`，重新按目录传一次即可。

### 4.4 开启 Pages

1. 仓库页面 → `Settings` → 左侧 `Pages`。
2. **Source** 选 `Deploy from a branch`。
3. **Branch** 选 `main`，目录选 `/ (root)`，点 `Save`。
4. 等 1~2 分钟，刷新页面，顶部会出现你的网址：

   ```
   https://你的用户名.github.io/meeting/
   ```

5. 打开它 —— 这就是你的系统网址，**记下来，以后一直用它**。

### 4.5 以后怎么更新

改完 `config/config.js` 或代码后：仓库页面 → 点进对应文件 → 右上角铅笔图标 → 改完 `Commit changes`。
或者重新走一遍 4.3 上传覆盖（同名文件会被替换）。改完等 1 分钟，刷新网页即可生效。

### 4.6 如果 github.io 打不开（备用方案）

`github.io` 在国内偶尔不稳定。整套代码是纯静态的，可以原样搬到别处：

| 平台 | 做法 |
| --- | --- |
| **Gitee Pages** | 把仓库同步到 Gitee，开启 Gitee Pages 服务（需实名，免费版要手动更新） |
| **Cloudflare Pages** | 把文件夹拖到 Cloudflare Pages 上传区，得到一个 `*.pages.dev` 网址 |
| **校园内网 / 自己的服务器** | 把这些文件丢进任意 Web 目录即可，无需 PHP/数据库 |

三种方式都**不用改一行代码**（`config/config.js` 里的 Supabase 参数照旧有效）。只有网址变了，参会链接会自动跟着变。

## 5. 日常使用流程

### 发一场会

1. 打开后台 → **发布会议**。
2. 填会议名称（必填）、日期时间、地点、主办部门、主持人、联系人、议程。
3. 需要的话设**填报截止时间**（到点后链接自动关闭，不能再提交）。
4. **选择参会人员**：
   - 点类别标签（如"处长"）→ 该类全部加入，人数自动跳出。
   - 或在搜索框输入姓名/部门 → 单独勾选。
   - 右上角"已选 N 人"实时显示总数。
5. 点 **发布会议并生成链接**。
6. 跳到会议详情页 → 复制链接 或 点"显示二维码" → **发到微信群 / 钉钉群**。

### 别人怎么填

打开链接 → 看到会议信息（日期、时间、地点、主办、议程）→ 填自己姓名 → 点"参加"或"不参加" → 不参加要填一句原因 → 提交 → 出现"已确认参会"。

> 姓名输入框会**自动提示受邀名单里的名字**，减少写错字。填了名单外的名字也能提交，但后台会标红"名单外"，需要你人工核对。

### 你看结果

- **会议看板**：每场会议一个窗格，绿色=参会、红色=不参会、黄色=待确认，还有回执率。
- **点开窗格**：完整的参会人员表，可按"已确认参会 / 不参会 / 待确认"筛选；每 30 秒自动刷新，也可以点"⟳ 刷新回执"手动刷。
- 每行显示：姓名、类别、部门、是否参会、不参会原因、备注、回执时间。

### 催办

对着"待确认"筛选出来的名单，把链接再发一次即可。

## 6. 名单管理

进入 **名单管理** 页：

| 操作 | 说明 |
| --- | --- |
| 修改 | 直接在表格里改部门 / 类别 / 姓名 / 手机号 / 备注，**点走即自动保存**（Enter 也可） |
| 新增一人 | 右上角"＋ 新增一人"，然后在表格里改信息 |
| 删除 | 每行右侧"删除"；勾选多行后可"删除选中 N 人" |
| 从 Excel 导入 | 见下方说明 |
| 下载导入模板 | 得到一份格式正确的空表 |
| 导出当前名单 | 导出成 Excel |
| 写入初始 55 人名单 | 一键导入你原来那份《机关部处长、办公室主任、院长、党总支书记.xlsx》的 55 人 |

### Excel 导入的格式要求

只需要一个大致的表头即可，**列的顺序随意**，程序按表头文字自动认列：

| 列名（任选其一即可被识别） | 是否必须 |
| --- | --- |
| 姓名 / 名字 | ✅ 必须 |
| 部门 / 单位 / 学院 / 处室 | 建议有 |
| 类别 / 分类 / 身份 / 职务类型 | 建议有 |
| 手机号 / 电话 / 联系方式 | 选填 |
| 备注 / 说明 | 选填 |
| 序号 / 编号 | 选填（用于排序） |

- 支持 `.xlsx` 和 `.csv`。
- **不认老式 `.xls`** —— 请在 Excel 里"另存为" `.xlsx` 再导入。
- 如果完全没有表头，程序按 `序号, 部门, 类别, 姓名` 的位置推断。
- 导入时按「**部门 + 类别 + 姓名**」三者合并：完全相同则更新，否则新增。所以**重复导入同一份表不会产生重复数据**，可以放心反复导。
- 表格中间有空行会自动跳过。

### 一个重要细节

你在**名单管理里改名单，不会影响已经发布过的会议**。因为每场会议在发布时会把当时的参会人名单"拍一张快照"存进这场会议里。这样做的目的是：历史会议的参会范围永远保持原样，以后统计不会被后来的名单变动搞乱。

如果某场会议确实要改参会人员，直接 **编辑该会议** 重新勾选即可。

## 8. 数据存在哪里、备份怎么做

- 所有会议、回执、名单都存在**你自己的 Supabase 项目**里，不在 GitHub 上。
- GitHub 上只有网页代码，**没有任何会议数据**。所以就算仓库公开，别人也看不到你的会议内容。
- 数据不会过期，Supabase 免费版对这类小规模使用完全够（免费额度 500MB 数据库）。但**免费项目长时间完全不活动可能被暂停**，建议偶尔登录看一眼；真被暂停了，在控制台点一下就能恢复，数据还在。

### 备份（建议每月做一次）

最简单可靠的备份就是**导出**：

1. 后台 → 导出统计 → `导出全部会议` → 存到电脑/网盘。
2. 后台 → 名单管理 → `导出当前名单` → 一起存。

两份文件合起来就是完整的数据快照。即使将来换了系统，Excel 也照样能看。

### 在 Supabase 里直接看数据（进阶）

`Table Editor` → 选 `meetings` / `responses` / `roster` 表 → 可以像 Excel 一样浏览，也能导出 CSV。

## 9. 常见问题

**Q：打开后台提示"连接云端失败"？**
A：检查 `config/config.js` 里的 `SUPABASE_URL` 是否以 `https://` 开头、`SUPABASE_ANON_KEY` 是否完整（很长一串），以及这台电脑能不能上网。

**Q：提示"后台口令不正确"？**
A：口令必须与你执行 `select public.set_admin_secret('...')` 时设的完全一致（区分大小写）。忘了就在 SQL Editor 里重设一次。

**Q：提示"数据库里还没有建表"？**
A：`supabase/01_schema.sql` 没执行成功，回到 3.2 重做。注意要**整段**粘贴，不要漏掉开头 `create extension` 那几行。

**Q：执行 SQL 时报 `ERROR: 42883: function digest(text, unknown) does not exist`？**
A：这是 pgcrypto 扩展的问题——你项目里的 `digest()` 不在默认搜索路径能命中的位置。

**最新版脚本已经把所有 pgcrypto 依赖都去掉了**（口令改用 PostgreSQL 内置的 `pg_catalog.sha256`，
分享链接的随机串改用内置 `md5()`），不该再出现这个错。请确认你用的是最新版 `01_schema.sql`：

- 第 9 行左右应该是 `set search_path = public, extensions;`
- 第 6 节里应该出现 `pg_catalog.sha256`，**不应**再出现任何 `digest(`
- `share_token` 那一行应该是 `md5(random()::text || clock_timestamp()::text)` 开头

确认无误后整段重跑一次即可。

> 上一次报错的那次执行是**整体回滚**的，一张表都没建成，所以直接重跑不会留下半成品。

跑完后可以在 SQL Editor 里做两个只读自检：

```sql
-- 应该返回 64 位十六进制
select public.admin_secret_hash('测试口令') as 哈希值;

-- 应该返回 4 行函数名
select proname from pg_proc
 where pronamespace = 'public'::regnamespace
   and proname in ('admin_secret_hash','set_admin_secret','check_admin','req_secret')
 order by proname;

-- 应该返回 3 行表名
select tablename from pg_tables
 where schemaname = 'public' and tablename in ('roster','meetings','responses')
 order by tablename;
```

**Q：参会人说打不开链接？**
A：① 确认会议已发布（不是草稿）；② 让他在浏览器地址栏里完整粘贴，别只复制一部分；③ 如果 `github.io` 他那边打不开，按 4.6 换托管平台。

**Q：同一个"张静"填了两次，会不会算两个人？**
A：不会。系统按**姓名**去重（去掉空格、忽略大小写），同一个人重复提交只会**更新**上一次的结果。所以如果参会人打错字重新填，后台可能出现两条 —— 这时你在详情页看到"名单外"标记，删掉错的那条即可（Supabase 表的 `responses` 里删，或告诉我加一个删除按钮）。

**Q：两个人真的同名怎么办？**
A：目前的姓名匹配会把同名视为同一人。你这份 55 人名单里没有重名，暂时不影响。如果以后遇到重名，可以改成"部门+姓名"匹配 —— 需要调整一处代码，跟我说即可。

**Q：邀请的人数会随名单变化吗？**
A：不会。会议发布时的人数就是快照，之后改名单不影响它（见第 6 节末尾）。

**Q：有人乱填、填一堆假名字怎么办？**
A：列表里有"名单外"标记，一眼就能看出来。也可以点开会话详情把无关记录删掉。想更严一点可以加"手机号后四位核验"，需要名单里有手机号。

**Q：二维码扫不出来？**
A：生成的二维码已用专业解码器验证可识别。如果截图发到微信被压缩了，让对方长按图片"识别图中二维码"，或直接点链接。

**Q：能不能加"随行人数""用餐需求"？**
A：能。数据库已经预留了"备注"字段可以直接写。要独立字段（比如随行人数）需要加一列并改表单，告诉我即可。

## 10. 安全说明

请了解这几条，心里有数：

1. **网页源码里的 `SUPABASE_ANON_KEY` 是设计上就要公开的**（Supabase 的 anon key 本就用于前端）。真正拦人的是数据库里的安全策略（RLS）和你的**后台口令**。
2. **`service_role` 密钥绝对不能放进这个项目** —— 它绕过所有安全策略。
3. 没有正确口令时，数据库**拒绝**读取名单、会议和任何回执。这条是靠数据库层面的策略强制的，不是靠前端藏起来。
4. **参会人只能看到自己那场会议的公开信息**（会议名称、时间、地点、议程）和受邀人**姓名**列表（用于输入提示），**看不到**别人的参会状态、请假原因、备注。
5. **参会链接本身是可猜不出的随机串**（9 字节随机），但请只发给应该收到的人。链接泄露 = 对方能看到那场会议的信息并提交回执。
6. 后台口令保存在**你这台电脑的浏览器**里（localStorage），明文。别在公用电脑上勾选记住口令；用完可以在浏览器里清除站点数据。
7. **建议**：如果你觉得 `ADMIN_SECRET` 写进 `config/config.js` 再传到公开仓库不妥（虽然仓库里只有口令、没有数据），那就**留空**，改为每次手输口令 —— 这样仓库里就不含口令。
8. 数据库里的所有写入都有网络传输加密（HTTPS）。
