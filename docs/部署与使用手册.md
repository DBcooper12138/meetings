## 1. 三个角色

| 角色 | 能做什么 | 怎么获得 |
| --- | --- | --- |
| **普通用户** | 管理自己的名单；发布自己的会议；看自己的会议统计；充值、买套餐 | 自己注册（工号+姓名+手机号+邮箱），邮箱验证后即可 |
| **参会人** | 打开链接 → 填姓名 → 选参加/不参加 → 填原因/备注 | 不需要注册，谁拿到链接都能填 |
| **超级管理员** | 查看和修改所有用户；锁定账号；设置套餐价格；审批充值；查看所有人的会议 | 由你在数据库里指定（见第 4 节） |

**数据隔离**：普通用户之间**互相看不到**对方的名单、会议和统计。这条是数据库层面（RLS）强制的，不是靠前端隐藏。超级管理员可以看全部。

### 1.1 权限与额度对照表

| 能力 | 免费 / 已过期 | 会员（套餐有效） | 超级管理员 |
| --- | --- | --- | --- |
| 登录、改自己资料 | ✅ | ✅ | ✅ |
| 维护自己的名单（增删改 + Excel 导入） | ✅ | ✅ | ✅ |
| 查看自己的会议与统计 | ✅ | ✅ | ✅ |
| **发布会议** | **最多 1 场** | ✅ 不限场次 | ✅ 不限 |
| **单场邀请人数** | **最多 20 人** | ✅ 不限 | ✅ 不限 |
| **复制催办文本** | **10 次** | ✅ 不限次数 | ✅ 不限 |
| **名单外人员一键加入名单** | **10 次** | ✅ 不限次数 | ✅ 不限 |
| **导出**（会议/统计/名单） | ❌ 点击会提示购买 | ✅ | ✅ |
| 购买套餐、申请充值 | ✅ | ✅ | ✅ |
| 管理其他用户、定价、审批充值 | ❌ | ❌ | ✅ |
| 锁定账号后 | 能登录、能看，**不能发会**，其会议链接**暂停接收回执** | 同左 | — |

> **新注册用户没有试用期**，注册完就是"免费额度"，想发更多会议需先充值买套餐。
> 需要给某人开通试用或赠送，由超级管理员在「用户管理 → 套餐」里手动操作。
> 套餐到期后自动回到"免费额度"，**历史数据全部保留**，续费即刻恢复完整功能。
>
> 两个"10 次"的配额是**按账号累计**的，用完后购买套餐即可无限使用；
> 会员在有效期内用这两个功能**不再累计次数**。
> 超级管理员可以在数据库里把某个用户的配额清零（`quota_remind_used` / `quota_promote_used`）。
>
> 这些限制**都在数据库里强制执行**（发布会议的触发器 `check_meeting_allowed`、
> 配额函数 `consume_quota`），不是靠前端藏按钮 —— 绕过界面直接调接口也会被数据库拒绝。
> 唯一的例外是"导出"：因为数据本来就属于用户自己（他能在页面上看到），
> 导出按钮只是一个界面限制，无法从技术上阻止他手动复制。

## 2. 第一次部署（约 30 分钟）

### 2.1 建 Supabase 项目

1. 打开 <https://supabase.com> 注册并新建项目
2. **Region 选 Singapore**（国内访问最快）
3. 等 1~2 分钟初始化完成

### 2.2 建库（一条 SQL 全搞定）

1. 左侧 **SQL Editor → New query**
2. 用记事本打开项目里的 **`supabase/01_schema.sql`**，**整段**复制粘贴
3. 点 **Run**，应显示 `Success. No rows returned`

这一步会建好：
- 7 张表（用户档案、套餐、钱包流水、充值申请、名单、会议、回执）
- 全部函数（注册自动建档、买套餐、充值审批、超管操作、参会人填报等）
- 全部行级安全策略（数据隔离）
- 3 个默认套餐（月卡/季卡/年卡，价格可改）

> **从 v1 升级**：直接执行这个脚本即可。脚本会自动清理旧版的"后台口令"方案，并保留你已有的会议、名单、回执数据（旧数据没有归属用户，只有超管看得到，见第 4.3 节可归到你名下）。

### 2.3 填配置

打开 **`config/config.js`**，把两个值填进去：

```js
SUPABASE_URL: 'https://你的项目名.supabase.co',   // 只填域名，不要带 /rest/v1/
SUPABASE_ANON_KEY: 'eyJhbGciOi...（anon public 密钥）',
```

位置：Supabase → `Project Settings` → `Data API`（Project URL）和 `API Keys`（anon public）。

> ⚠️ `ADMIN_SECRET` 这一项在 v2 已经**不再使用**，留空即可。v2 用的是真正的账号登录。

### 2.4 上传 GitHub Pages

1. 新建仓库（**Public**）
2. 上传：`index.html`、`css/`、`js/`、`config/`、`supabase/`、`docs/`、`README.md`
3. **不要传 `_dev/`**
4. `Settings` → `Pages` → Source 选 `Deploy from a branch` → `main` + `/ (root)` → `Save`
5. 等 1~2 分钟，得到网址：`https://用户名.github.io/仓库名/`

> 注意：注册要收邮件，所以**必须用 https 网址**，本地 `file://` 双击打开无法完成注册流程。

## 3. Supabase 认证设置（邮件验证关键）

去 Supabase 控制台 **`Authentication`**，按下面四步配置。**不做这一步，注册和重置密码都跑不通。**

### 3.1 打开邮箱注册 + 邮箱验证

`Authentication` → `Sign In / Providers` → **Email**：
- ✅ Enable Email provider
- ✅ **Confirm email**（开启后，注册要验证邮箱才能登录）

> 如果不想让用户验证邮箱（省事但安全性低），把 **Confirm email 关掉**。关掉后注册直接成功、直接能登录，本系统会自动适配。

### 3.2 填网址白名单（必做，否则邮件链接会跳到 localhost）

`Authentication` → `URL Configuration`：

| 项 | 填什么 |
| --- | --- |
| **Site URL** | `https://用户名.github.io/仓库名/` |
| **Redirect URLs** | 加上一条 `https://用户名.github.io/仓库名/**` |

末尾那两个星号 `**` 是**通配符**，不是网址的一部分。

| 写法 | 允许跳回的地址 |
| --- | --- |
| `https://张三.github.io/meeting/` | **只有**这一个，多一个字符都不行 |
| `https://张三.github.io/meeting/**` | 这个前缀下的**任何路径和参数**都允许 |

必须用带 `**` 的写法，因为本系统跳转时会在网址后加参数：

```
https://张三.github.io/meeting/?goto=reset             ← 重置密码点邮件链接回来
https://张三.github.io/meeting/?goto=login&confirm=1   ← 注册后点验证链接回来
```

只填裸地址的话，Supabase 会判定 `?goto=...` 不在白名单里，邮件链接点开就报错或跳回 localhost。

> 本地调试时再加一条 `http://localhost:8000/**`（端口按你实际用的填）。

### 3.3 邮件模板（可选，看你要不要"验证码"）

> **先说结论：不改模板也能完整使用。**
> 新版 Supabase 有个限制：**没配自定义 SMTP 时，邮件模板是只读的**
> —— 页面会显示 `Set up custom SMTP to edit templates`，正文区域是灰色占位、点不进去。
> 这是 Supabase 的限制，不是你操作错了。

本系统支持两种验证方式，**任选其一**：

| 方式 | 要改模板吗 | 用户体验 |
| --- | --- | --- |
| **点邮件里的链接**（默认，推荐先用） | ❌ 不用 | 邮件里只有一个链接，点一下自动回本站并登录 / 进入改密码页 |
| **输入邮件里的 6 位验证码** | ✅ 要改模板（也就意味着要先配 SMTP） | 用户手输 6 位数字 |

#### 路线 A：不改模板（现在就能跑通）

什么都不用做。

- **注册**：填表提交 → 收邮件 → 点邮件里的 `Confirm your email address` 链接 → 自动回你的网址并**直接登录**
- **忘记密码**：填邮箱 → 收邮件 → 点邮件里的 `Reset password` 链接 → 回到「设置新密码」页，直接设新密码

> 代码已经按这条路优化过：用的是 implicit 流程，**邮件链接在手机、电脑、甚至换浏览器打开都有效**。
> （如果换成 PKCE，链接必须在"申请时那台浏览器"里点，电脑申请、手机点开就会失败。）

#### 路线 B：想要 6 位验证码（必须先配 SMTP）

1. 在 `Emails` 页面点那个 **`Set up SMTP`** 按钮（或 `Project Settings → Authentication → SMTP Settings`），
   按 3.4 节的表格填好你自己的邮箱 SMTP，保存。
2. 配好后回到 `Authentication → Emails`，模板就**变成可编辑**，`Body` 区域变成真正的 HTML 编辑框。
3. 先点左侧模板 `Confirm sign up`，编辑区分上下两块：上面 `Subject`（邮件标题），下面 `Body`（正文）。
4. 把 `Body` 整段替换成：

```html
<h2>确认你的邮箱</h2>
<p>你的验证码是：<b>{{ .Token }}</b>（10 分钟内有效）</p>
<p>也可以直接点这个链接完成验证：<a href="{{ .ConfirmationURL }}">立即验证</a></p>
<p>如果这不是你本人的操作，请忽略这封邮件。</p>
```

5. 再点左侧 `Reset password`，`Body` 整段替换成：

```html
<h2>重置密码</h2>
<p>你的密码重置验证码是：<b>{{ .Token }}</b>（10 分钟内有效）</p>
<p>或点此链接重置：<a href="{{ .ConfirmationURL }}">重置密码</a></p>
<p>如果这不是你本人的操作，请忽略这封邮件。</p>
```

6. 两个模板**各保存一次**（改完一个点一次 Save）。

> - `{{ .Token }}` 是 Supabase 自动生成的 6 位数字，每次不同。
> - 两段都保留了 `{{ .ConfirmationURL }}`，所以"点链接"和"输验证码"两种方式都能用。
> - 只改注册模板、不改重置模板，会出现"注册能收到码、改密码收不到"的错位；反之亦然。


### 3.4 自定义 SMTP（强烈建议，尤其人多时）

Supabase 自带的邮件服务**限制很严**：默认每小时只能发几封，而且容易进垃圾箱。
**这会直接卡住注册** —— 多来两个人就发不出验证邮件了。

配置入口二选一：
- `Authentication → Emails` 页面上那个 **`Set up SMTP`** 按钮
- 或 `Project Settings → Authentication → SMTP Settings`

打开 `Enable Custom SMTP` 后填：

| 服务商 | Host | Port | 说明 |
| --- | --- | --- | --- |
| 腾讯企业邮 | `smtp.exmail.qq.com` | 465（SSL） | 邮箱地址 + 客户端授权码 |
| 阿里云邮箱 | `smtp.mxhichina.com` | 465（SSL） | 同上 |
| QQ 邮箱 | `smtp.qq.com` | 465（SSL） | 需在 QQ 邮箱设置里开启 SMTP 并拿授权码 |
| 163 邮箱 | `smtp.163.com` | 465（SSL） | 同上 |

同时把 `Sender email` 改成你的邮箱，`Sender name` 填「会议系统」之类。

> 配好 SMTP 有两层好处：① 邮件能稳定大量发送，注册不再卡；② **邮件模板解锁可编辑**（想要 6 位验证码就按 3.3 路线 B 改）。**代码不用改**。

#### 3.4.1 用 QQ 邮箱做发信（详细步骤）

**第一步：拿到 QQ 邮箱的「授权码」**（这是关键，不是 QQ 登录密码）

1. 浏览器登录 <https://mail.qq.com>
2. 左侧边栏点 **`账号与安全`** 这一项
   - 注意：它右边带一个 ↗ 图标，点了会**跳到另一个设置页**（可能是新标签页，注意看）
   - 旧版界面里这一项叫 **`账号`** 或 **`账户`**，在「设置」下的二级菜单里
3. 在新页面的 **「POP3/IMAP/SMTP/Exchange/CardDAV/CalDAV 服务」** 区域
4. 点 **「IMAP/SMTP 服务」** 后面的 **`开启`**
5. 按提示做一次安全验证（手机发短信 / 密保）
6. 弹出框里会显示一串 **16 位字母**的「授权码」—— **复制它**，这就是后面要填的"密码"

> 找不到那一段的话，在设置页按 `Ctrl + F` 搜 **`SMTP`** 或 **`授权码`**，直接跳过去。
> 授权码只显示一次，关掉窗口就看不到了，可以重新生成一个。
> 别把 QQ 登录密码填进 SMTP 密码框，那一定会报 535 认证失败。

**第二步：在 Supabase 里填**

`Authentication → Emails` → 点 **`Set up SMTP`**（或 `Project Settings → Authentication → SMTP Settings`）
→ 打开 `Enable Custom SMTP` → 按下表填：

| Supabase 字段 | 填什么 | 示例 |
| --- | --- | --- |
| **Host** | `smtp.qq.com` | `smtp.qq.com` |
| **Port** | `465`（SSL） | `465` |
| **Username** | 你的完整 QQ 邮箱 | `123456789@qq.com` |
| **Password** | 上一步拿到的 **16 位授权码** | `abcdwxyzefghijkl` |
| **Sender email** | 必须和 Username **完全一致** | `123456789@qq.com` |
| **Sender name** | 发件人显示名 | `会议系统` |

点 **Save**。

> ⚠️ `Sender email` 千万不能填别的地址（比如 `noreply@学校域名`）。
> QQ 邮箱不允许冒用发件人，不一致会报 `550 Invalid sender`。
> 想用自己域名做发件人，得用腾讯企业邮（见下表），不要用个人 QQ 邮箱。

**第三步：验证**

去你网站点一次「忘记密码」→ 填你的 QQ 邮箱 → 看能不能收到重置邮件。

- 收不到先查 **垃圾邮件** 文件夹
- 能收到 → SMTP 配通了，这时回到 `Authentication → Emails`，模板已经**变成可编辑**，可以按 3.3 路线 B 粘 6 位验证码模板了

**QQ 邮箱的限制（心里有数）**

| 限制 | 说明 |
| --- | --- |
| 每日发信量 | 个人 QQ 邮箱有每日上限（新号更低），几十人注册时够用，上百人可能不够 |
| 收件方拦截 | 发到校外陌生域名的邮箱时，容易被判垃圾邮件 |
| 发件人必须是本人 | 不能自定义发件人地址 |

> 如果你要在全校范围用、注册量大，建议换成**腾讯企业邮 / 阿里云邮箱**（`smtp.exmail.qq.com` / `smtp.mxhichina.com`，端口同样 465），
> 它们允许自定义发件人域名、每日额度高得多，配置方式完全一样，只是 Host 和账号换成企业邮箱的。

**常见报错对照**

| 报错 | 原因 | 解决 |
| --- | --- | --- |
| `535 Login fail` / 认证失败 | 密码框填了 QQ 登录密码，或授权码错了，或 IMAP/SMTP 服务没开启 | 重新生成授权码，确认服务已开启，只填 16 位授权码 |
| `550 Invalid sender` | Sender email 与登录的 QQ 邮箱不一致 | 改成完全一致 |
| 连接超时 / timeout | 465 端口被网络拦住 | 把 Port 改成 `587` 再试（STARTTLS） |
| 收件箱没有、垃圾箱有 | 收件方判定为营销邮件 | 让收件人把发件地址加白名单；或换企业邮箱 |

#### 3.4.2 其他邮箱的参数

| 服务商 | Host | Port | 密码填什么 | 能否自定义发件人 |
| --- | --- | --- | --- | --- |
| 腾讯企业邮 | `smtp.exmail.qq.com` | 465 | 邮箱密码或客户端专用密码 | ✅ 可（需在后台加别名） |
| 阿里云邮箱 | `smtp.mxhichina.com` | 465 | 客户端授权码 | ✅ 可 |
| QQ 个人邮箱 | `smtp.qq.com` | 465 | 16 位授权码 | ❌ 只能本人 |
| 163 邮箱 | `smtp.163.com` | 465 | 客户端授权码 | ❌ 只能本人 |

## 4. 指定超级管理员（必做）

### 4.1 先注册一个账号

打开你的网址 → **注册新账号** → 填工号、姓名、手机号、邮箱、密码 → 验证邮箱 → 登录。

### 4.2 在 SQL 里把它设成超管

Supabase → SQL Editor → New query，执行（换掉工号）：

```sql
update public.profiles set is_super = true where emp_no = '你的工号';
```

确认一下：

```sql
select emp_no, name, email, is_super, locked, balance_cents, plan_expires_at
  from public.profiles order by created_at;
```

看到你那一行 `is_super = t` 就成功了。**刷新网页**，左侧会多出「超级管理员」菜单。

> 执行完把 SQL 删掉，别留在历史里。

### 4.3（可选）把 v1 的老数据归到你名下

旧版（单管理员）时期的会议和名单没有归属用户，普通用户看不到。执行下面两句把它们归给你：

```sql
update public.meetings set owner_id = (select id from public.profiles where emp_no = '你的工号')
 where owner_id is null;
update public.roster set owner_id = (select id from public.profiles where emp_no = '你的工号')
 where owner_id is null;
```

## 5. 注册与登录

### 注册

打开网址 → **注册新账号**，填：

| 字段 | 要求 |
| --- | --- |
| 工号 | 2-20 位字母/数字/-_. ，**全系统唯一** |
| 姓名 | 真实姓名 |
| 手机号 | 11 位手机号 |
| 邮箱 | 用来收验证码和重置密码 |
| 密码 | 至少 8 位，必须同时含字母和数字 |

注册后：
- 开启了邮箱确认 → 跳到「验证邮箱」页 → 去邮箱**点验证链接**（点完自动回来并登录）
- 关闭了邮箱确认 → 直接回登录页登录

> 邮件里有没有 **6 位验证码**，取决于你是否配了自定义 SMTP 并改了模板（见 3.3）：
> 没配的话邮件里只有链接，**点链接就行**，不用找验证码。

### 登录 / 忘记密码

- 登录：邮箱 + 密码
- 忘记密码：点「忘记密码？」→ 填邮箱 → 收 6 位验证码 → 填验证码 + 新密码
- 登录后可在「我的账户」里改姓名、手机号、密码

## 6. 我的账户：套餐与充值

页面自上而下分四块：

1. **账号资料 + 套餐与余额** —— 改姓名/手机号/密码；看套餐状态和余额
2. **会员权益对比表** —— 免费额度与会员逐项对比，**高亮的那一列就是用户当前的权益**，
   有差异的行会标「差异」标签；非会员时右上角有「去购买套餐」按钮，点了直接滚到套餐区
3. **套餐卡片** —— 月卡/季卡/年卡，点「购买」用余额支付
4. **充值申请 + 账单流水**

### 套餐规则

- 按**时长**计费：买一个月卡，30 天内**发布会议不限场次、不限邀请人数、可导出**
- 再次购买会**从当前到期日顺延**（不浪费剩余天数）
- 套餐过期后**不能发布新会议**，但已发布的会议、参会链接、历史数据**全部保留**，续费即恢复
- **新注册用户没有试用期**，注册后直接是免费额度（需要赠送体验由超管在「用户管理 → 套餐」手动开通）
- 免费额度（未开通/已过期）：**最多 1 场会议、单场最多 20 人、复制催办 10 次、一键加入名单 10 次、不能导出**（详见 1.1 节）
- 超级管理员不受套餐限制

系统预置三个套餐（月卡 99 元 / 季卡 268 元 / 年卡 899 元），价格由超管随时改。

### 充值流程

目前**没有接在线支付**（微信/支付宝真实收款需要企业商户号 + 服务端验签，无法只靠静态网页安全实现）。现在的流程是：

1. 用户在「我的账户」点 **申请充值** → 填金额 + 到账方式 + 说明
2. 用户线下把钱转给你
3. 你在「超级管理员 → 充值审批」里核对 → 点 **通过**
4. 金额立即计入该用户余额，同时生成一条账单流水

用户能在账户页看到每条申请的审批状态。

### 余额与账单

- 买套餐时自动扣减余额
- 「账单流水」记录每一笔充值、购套餐、管理员调整
- 超管也可以直接给某个用户**调整余额**（正数增加、负数扣减，需填原因）

## 7. 发布会议与名单（含工号）

### 名单管理

进入 **名单管理**，每个用户看到的都是**自己那份名单**。

页面顶部会显示一行状态，用来确认数据存到了哪里：

> 当前账号：**张三**（工号 1001）　数据位置：**Supabase 云端**。
> 换电脑、换浏览器、换手机登录同一个账号，看到的都是同一份名单；其他账号看不到你的名单。

表格列：`工号 | 姓名 | 类别 | 部门 | 手机号 | 备注`（工号在姓名前）。直接在表格里改，**点走自动保存**。

| 按钮 | 作用 |
| --- | --- |
| ＋ 新增一人 | 加一行空白记录 |
| 从 Excel 导入 | 见下方 |
| 下载导入模板 | 格式正确的空表（**工号在姓名前一列**） |
| 导出当前名单 | 导出 Excel |
| 写入初始 55 人名单 | 一键导入原来那份 55 人名单（工号列留空，之后可补） |

### Excel 导入格式

列顺序随意，程序按表头文字自动认列：

| 列名 | 是否必须 |
| --- | --- |
| **工号** / 员工号 / 职工号 | 建议有 |
| **姓名** / 名字 | ✅ 必须 |
| 部门 / 单位 / 学院 / 处室 | 建议有 |
| 类别 / 分类 / 身份 / 职务类型 | 建议有 |
| 手机号 / 电话 / 联系方式 | 选填 |
| 备注 / 说明 | 选填 |
| 序号 / 排序 | 选填 |

- 支持 `.xlsx` 和 `.csv`；**不认老式 `.xls`**（请另存为 .xlsx）
- 按「**部门 + 类别 + 姓名**」合并：完全相同则更新，否则新增 —— **重复导入不会产生重复数据**
- 同一个人在同一部门有两种身份（如既是办公室主任又是院长）会**分别保留两条**

### 发布会议

1. **发布会议** → 填名称（必填）、日期时间、地点、主办部门、主持人、联系人、议程
2. 可设**填报截止时间**
3. **选择参会人员**：
   - 点类别标签（如「处长」）→ 整类加入
   - 或搜索姓名/工号/部门 → 单独勾选
   - 右上角实时显示"已选 N 人"
4. 点 **发布会议并生成链接** → 跳到详情页

### 用历史会议作模板（重复会议一键复制）

在**会议看板**上，每张会议卡片底部有 **`作模板新建`** 按钮：

1. 点它 → 确认 → 跳到「发布新会议」页
2. 自动带过来：会议名称、开始/结束时间、地点、主办部门、主持人、联系人、议程、
   是否收集请假原因/备注、**以及原来的参会人员名单**（按当前名单重新匹配，已选人数会显示出来）
3. **会议日期会重置为今天**（避免误发到过去的日期），填报截止时间清空
4. 改完点「发布会议并生成链接」就是一场新会议，历史会议完全不受影响

> 适合"每周例会""每月例会"这种固定人员、固定议程的会议。
> 如果原会议的某个参会人后来被从名单里删掉了，他不会出现在新会议里（提示里会说明）。

### 把链接发给参会人

详情页可以：
- **复制链接** → 发到微信群
- **显示二维码** → 截图发群，手机扫码打开
- **复制催办文本** → 自动列出还没确认的人名 + 链接，直接粘到群里

参会人打开链接：看会议信息 → **填工号 + 姓名**（姓名会自动提示名单里的名字）→ 点「参加」或「不参加」→ 不参加要填原因 → 提交。**截止前可重复提交修改**。

> **为什么必须填工号**：工号是唯一标识，用来区分同名的人。
> 只填姓名的话，两个"张伟"会被系统当成同一个人，后填的会覆盖先填的。
> 匹配顺序是：先按工号在受邀名单里找 → 找不到才退回按姓名匹配（兼容老数据）。
> 填了工号后再打开链接，会自动带出他上次的答复。

详情页每 30 秒自动刷新回执。

### 名单外的人来参会了怎么办（一键加入名单）

有时候会议链接被转发，来了个**不在名单里**的人填了回执。系统会在详情页的表格里把他标成
橙色的 **`名单外`** 标签，并在最后一列 **「操作」** 给出按钮：

| 情况 | 按钮 | 点了以后 |
| --- | --- | --- |
| 不在名单里、还没加过 | **`加入名单`** | 把他的姓名/工号/部门/类别写进你的名单，按钮变成 `已加入名单` |
| 已经在名单里（同工号，或同部门同姓名） | `加入名单` | 只标记为已加入，**不扣配额**、不重复添加 |
| 本来就在受邀名单里 | — | 不显示按钮（不需要加） |

他的部门、类别、工号直接取自他自己的回执，不用你手填。之后新建会议时，就能在名单里勾到他。

> **免费额度**：这个功能免费用户可用 **10 次**，用完后提示购买套餐；会员不限次数。
> 剩余次数可以在会议详情页的按钮旁、以及「名单管理」页顶部看到。

### 复制催办文本（有次数限制）

待确认的人还没填时，点 **`复制催办文本`**，系统生成一段现成的话：

```
【参会确认提醒】XXXX会议
时间：…　地点：…
以下 12 位尚未确认，请点击链接填写：
张三、李四、…
确认链接：https://…
```

直接粘到微信群即可。**免费用户可用 10 次**，会员不限次数；按钮旁边会显示剩余次数。

| 控件 | 作用 |

| 指标 | 含义 |
| --- | --- |
| 被邀请次数 | 当前筛选范围内有多少场会议邀请了他 |

## 11. 常见问题

**Q：注册后登录提示"邮箱还没验证"？**
A：去邮箱**点验证链接**（没配 SMTP 时邮件里只有链接、没有验证码，这是正常的）。点完会自动回到本站并登录。
没收到先看垃圾箱；连续发不出说明触发了 Supabase 自带邮件的每小时限额 → 按 3.4 节配自定义 SMTP。

**Q：邮件模板页面是灰的，`Body` 点不进去、提示 `Set up custom SMTP to edit templates`？**
A：新版 Supabase 的规定：**没配自定义 SMTP 就不允许改邮件模板**。两条路：
① 不改模板，直接用邮件里的链接（本系统已支持，什么都不用做）；
② 先按 3.4 节配好 SMTP，模板自动解锁，再按 3.3 路线 B 粘贴模板。

**Q：点了邮件里的验证/重置链接，跳到 localhost 或 404？**
A：`Authentication → URL Configuration` 的 **Site URL** 和 **Redirect URLs** 没配成你的 GitHub Pages 网址。按 3.2 节改。

**Q：注册报"工号 xxx 已经被注册"？**
A：工号全局唯一。换一个，或找超管核对是不是别人填错了。

**Q：注册了但登录后提示"找不到你的账号档案"？**
A：`01_schema.sql` 没执行完整，`handle_new_user` 触发器没建。重新整段执行一遍脚本；已注册的用户需要删掉重注册（或在 SQL 里手动补一行 profiles）。

**Q：提示"套餐未开通或已过期，请先购买套餐"？**
A：普通用户必须先买套餐才能发布会议。让超管充值/调余额，然后去「我的账户」买套餐。超管自己不受限制。

**Q：普通用户之间能看到对方的会议吗？**
A：不能。数据库策略按 `owner_id` 隔离。如果发现能看到，说明 `01_schema.sql` 里的 RLS 部分没执行成功。

**Q：参会人链接打不开 / 提示"该会议已暂停"？**
A：① 发布会议的用户被锁定了 → 解锁即可；② 链接复制不完整；③ `github.io` 对方打不开，考虑换 Gitee Pages / Cloudflare Pages。

**Q：同一个"张静"填了两次算两个人吗？**
A：不算。按姓名归一化去重，重复提交只更新。

**Q：姓名真重名怎么办？**
A：当前按姓名匹配会把重名视为同一人。你这 55 人名单里没有重名。若以后遇到，需要改成"工号+姓名"匹配（改一处代码）。

**Q：改了名单，以前的会议会跟着变吗？**
A：不会。每场会议发布时会把参会人**快照**存进该会议，历史不受影响。

**Q：想加"随行人数""用餐需求"？**
A：现在可以用「备注」兜底；要独立字段需要加一列并改表单，告诉我即可。

## 12. 安全说明

1. **`SUPABASE_ANON_KEY` 放在前端是设计使然**（Supabase 的前端密钥本就公开）。真正的防线是数据库 RLS + 登录态。
2. **绝对不要把 `service_role` 密钥放进来** —— 它绕过所有安全策略。
3. 用户密码由 Supabase Auth 存储（bcrypt 哈希），**本系统任何地方都拿不到明文密码**。
4. 权限校验全部在数据库里：改档案走函数、买套餐走函数、锁定的判断在触发器里。前端算出来的东西不可信。
5. 参会人**不需要登录**，凭链接里的随机 token（32 字节十六进制）访问，只能看到该场会议的公开信息与受邀人姓名列表。
6. 参会人**看不到**别人的参会状态、请假原因。
7. 登录凭证保存在浏览器 localStorage（Supabase 标准做法）。公用电脑用完请点**退出登录**。
8. 全部传输走 HTTPS。
